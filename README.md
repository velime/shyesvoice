# shyesvoice — Windows TTS для Discord

Существующий интерфейс генерирует речь через Microsoft Edge TTS и воспроизводит
её через выбранное устройство вывода Windows. Discord-бот и токен не нужны.

**Схема:** интерфейс → Edge TTS → выбранный Windows Output → виртуальный кабель → микрофон Discord.

## Запуск

Требуются Windows 10/11, Python 3.11+, интернет для Edge TTS и FFmpeg.
Приложение сначала ищет `ffmpeg.exe` рядом с `main.py`, затем в PATH.

```powershell
python -m pip install -r requirements.txt
python main.py
```

Откройте http://127.0.0.1:5000. Собранный интерфейс уже находится в
`discord-tts-dashboard-ui/dist/index.html`; отдельный сервер Node не требуется.

Для пересборки интерфейса (Node.js 20.19+ или 22.12+):

```powershell
cd discord-tts-dashboard-ui
npm ci
npx tsc --noEmit
npm run build
```

## Выбор устройства

### Обычный микрофон через Soundpad

1. Запустите установленный Soundpad. Нужна версия с доступной командой добавления
   звуков через Remote Control API (пробная версия ограничивает эту команду).
2. В приложении выберите **Soundpad — Microphone** в списке **Playback Target**.
3. В Soundpad откройте **File → Preferences → Devices**, включите нужный микрофон
   и проверьте его статус. В Discord выберите тот же микрофон: кабель не нужен.

Голос и генерация Edge TTS остаются прежними. Soundpad получает команду играть
в выбранный в нём микрофон. Приложение связывается с уже запущенным Soundpad через
его официальный локальный API. Выбор микрофона находится в Soundpad: его Remote
Control API не предоставляет переключение устройств.

Чтобы одновременно слышать TTS самому, включите **Hear TTS locally** и выберите
наушники или динамики в **Local Monitor Device**. Приложение параллельно отправит
одну и ту же фразу в микрофон Soundpad и на выбранный локальный выход. Выбор
сохраняется между запусками. Если устройство мониторинга отключится, приложение
покажет ошибку и не перенаправит звук на другое устройство.

В Soundpad автоматически добавляется одна служебная запись **shyesvoice-live-tts**.
Она повторно используется для всех фраз; остальные записи не меняются. После
воспроизведения WAV заменяется короткой тишиной, чтобы не хранить произнесённый
текст в аудиофайле. Не используйте эту запись вручную одновременно с TTS.
Если Soundpad уже играет другой звук, TTS ждёт до 30 секунд. Режимы бесконечного
повтора и непрерывного воспроизведения в Soundpad следует отключить.
Если Soundpad закрыт или не отвечает, приложение показывает ошибку без перехода
на динамики. После запуска Soundpad нажмите Repeat или отправьте текст снова.

### Виртуальный кабель / обычный выход Windows

1. В **Playback Target** выберите нужный выход. На главном экране выбор сохраняется
   сразу; в **TTS Settings** нажмите **Save Settings**.
2. Для VB-CABLE выберите **CABLE Input (VB-Audio Virtual Cable)**.
3. В настройках голоса Discord выберите **CABLE Output (VB-Audio Virtual Cable)**
   как устройство ввода / микрофон. Discord запускается отдельно; API Discord
   приложение не использует.
4. Введите текст и нажмите Enter. Shift+Enter добавляет новую строку.

Список содержит активные выходы Windows и обновляется каждые 5 секунд,
при возвращении в окно и кнопкой Refresh. После установки драйвера кабеля
может потребоваться перезагрузка Windows. Само приложение драйверы не устанавливает.

Если Discord обрезает синтезированную речь, проверьте порог активации микрофона
и попробуйте отключить шумоподавление. При Push-to-Talk нужна соответствующая
клавиша Discord. Не включайте прослушивание кабеля через динамики, если не хотите
слышать его локально. Обычный микрофон не смешивается с TTS автоматически.

## Сохранённые возможности

- Те же голоса Edge TTS, фильтр голосов, скорость от −50% до +50%.
- Enter, Shift+Enter, Repeat, Clear Queue и Auto Speak после паузы 1,2 секунды.
- Прежняя компоновка, цвета, карточки, анимации и журнал действий.
- Playback Target занимает место прежней карточки Voice Channels.
- Clear Queue очищает ожидающие сообщения; текущая фраза доигрывает.

## Настройки и ошибки

`config.json` хранит голос, скорость, порт API и постоянные WASAPI ID основного
выхода и устройства локального мониторинга.
При переходе со старой версии голос и скорость сохраняются, а поля токена и
пользователя бота удаляются. Индексы и приблизительное совпадение названий
не используются: отключение устройства не перенаправит TTS на динамики.

Каждое сообщение запоминает устройство, голос и скорость при отправке.
Смена настроек применяется к новым сообщениям. Если устройство пропало,
сообщение завершается ошибкой в System Status / уведомлении; после повторного
подключения или выбора другого выхода можно отправить текст снова либо нажать Repeat.

Генерация выполняется в отдельном потоке очереди. Прежний генератор Edge TTS
пишет уникальный временный MP3, FFmpeg декодирует его в PCM в памяти, WASAPI
отправляет звук только на выбранный выход. Очередь просыпается сразу при отправке,
без прежнего интервала 0,5 секунды. Задержка генерации зависит от сети и длины текста.
Временный MP3 удаляется после успеха, ошибки или штатной остановки; интерфейсы
аудиоустройства освобождаются после проигрывания. Ctrl+C завершает сервер.

API привязан к 127.0.0.1. Не публикуйте его в интернете: авторизации в нём нет.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют миграцию настроек, точный выбор устройства без запасного выхода,
сохранение выбора, Repeat/Clear Queue, ошибки сети и устройства, восстановление
очереди и очистку временных файлов при отмене генерации.

При разработке выполнена реальная проверка Edge TTS → AudioRelay с одновременным
WASAPI loopback-измерением: выбранный виртуальный выход получил речь, стандартный
выход оставался без сигнала. VB-CABLE на проверяемой машине отсутствовал;
проверка самого драйвера VB-CABLE и приёма звука в Discord не выполнялась.
